# Async 512 generation plan
Preserve previous failed RPC and barrier-frontier results. Frozen width4 iterative2/4/6, completed trees only, no learning or deployment.
Implement eight CPU processes with independent suspended game slots, shared input/output storage, request IDs, bounded outstanding requests, arrival-driven GPU dispatch and game replenishment. No all-worker barrier inside generation. Seed groups remain separate.
Before measurement: CPU singleton must match reference value/action/nodes/cutoffs/RNG exactly. CUDA absolute value/logit tolerance 2e-5; report every action/tie discrepancy, no bit-equivalence claim. Atomic completed games survive restart; incomplete games restart from their own saved RNG.
Development: previous24/192 banks are development only. Measure64/128/256/512 active capacity; distinguish actual occupancy from capacity and NN batch. Profile and make separate justified revisions. Final new bank size and repeated comparison will be fixed after cost pilots, before final timing. Speed adoption requires faster end-to-end than CPU8 on both final repetitions with legal complete trajectories; no training otherwise.

Development revisions (before final timings): v1 removes barriers and pickled arrays using shared slots; v2 adds bit-exact unpackbits board encoding and explicit State copy (CPU singleton checks pass). v3 tests CUDA graph buckets because v1's 24-game diagnostic spends about 69% of group wall in forward/synchronization, with tiny actual batches. Graph batch/candidate padding can alter GEMM roundoff; the same predeclared 2e-5 absolute tolerance applies. Graph capture cost is included in end-to-end and reported separately. Graphs are inference-only and never modify the frozen model.
