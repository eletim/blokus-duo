# Root値補正の結論

既存低予算value/2plyを推奨のまま維持する。補正学生の棋力改善は確認できない。100ms教師は追加選択肢としてmain `cbe3b91`へ統合・push済み。教師の2標本の正の平均得点差は教師自身の結果であり、今回の学生へ流用しない。

## 実装と事前gate

全盤面6x14x14と状態49・候補39特徴を小型CNNへ入力し、同じ固定value/応手幅3のdepth4−depth2をroot点数で回帰。最終root選択へ `v2 + alpha*予測補正` を適用する。旧2plyの候補集合・順序・value本体・相手policyは変更していない。終局確定値は保護し、未知教師値はNaN＋mask、同値候補は許容集合として評価する。分類の単一正解化は行わない。

新24ゲーム48局面の教師情報上限診断で、同じ6候補以内のmaskでは28局面の選択損失が改善、平均0.753→0点。これは補正が最終選択に届くことを確認する限定診断であり、教師情報を安価に実現できた証拠でも学習成功でもない。実際のagent最終選択が補正で変わり2plyで上書きされないことをテストした。

事前計画に従い240ゲームから477局面（1重複除去）、381/48/48をゲーム単位train/dev/validationへ分離。初期値上位4と、残りから一様2候補を同depth4で完了評価。初期値による偏りがあり、ランダム候補もheuristic上位128内に限られる。教師は選択的探索で、厳密minimaxではない。主データは2,858ラベル、256,750探索node。更新seed1001/1002/1003は初期重み・データ・分割を共有し、minibatch乱数のみ異なる。

devで2設定へ絞り、新validation16prefix・先後交換・3seedの平均実戦得点差で共通3000更新/alpha0.5/25msを固定。旧探索に+1.771、zeroに+2.240、平均推論0.400msで事前gateを全通過した。CIはいずれも0を含み、採用根拠ではない。gate変更はしていない。旧holdoutは選択に使用していない。

## 固定後のfresh holdout

新seed1022000の96prefixを共有し、各seed先後交換。各比較576局だが、3seed×先後をprefix内平均してから96clusterでbootstrapした。3seedは独立データ再学習ではない。

旧探索との比較で実時間は学生17.558ms/手、旧17.401ms/手、超過2/8,842手と2/8,856手。zero比較では17.527対17.524ms。学生のfallbackは両比較とも0。全費用（合法手生成、候補入力作成、転送、GPU同期、推論、探索）を含む。実時間をpaddingで等しくした比較ではない。詳細の完了候補/node/超過率は `compute-summary.json`。

## 原因の切り分けと次案

- 補正を最終選択へ渡す配線は有効。devの同深度候補内regretはゼロ0.788から3seed平均0.532へ改善した。候補順だけ変えて最終値が上書きされた前方式の問題は解消した。
- しかし選択済みモデルのtrain MSEは約0.38、devは4.79（ゼロ4.38）。学習に未使用のsupervised validation48局面ではMSE約3.70（ゼロ2.86）、選択regret約0.590（ゼロ0.553）。この未使用ラベル診断は選択後にのみ実行し、再選択には使っていない。ゲームをまたぐ汎化の弱さ・過学習が見える。
- dev48局面の単独25ms診断では、観測済み教師最良候補を全seedで100%評価範囲に含んだ。全候補約89.5中完了は約31だが、今回の限定教師候補の取りこぼしでは説明できない。教師判断保持率は約50–54%、同じ完了候補の補正前は42–44%。この改善も実戦の改善には直結しない。
- 上位候補とランダム候補のラベル分布は異なる（平均補正+0.603対+0.866点）。未知候補の教師正解はない。全候補から選んだdevの手が教師ラベルを持つ割合は約96–98%に留まる。参照探索自体の評価誤差と選択偏りも残る。
- validation16prefixの最大成績による選択は分散が大きく、3000更新が予測MSEでは悪化しているのに選ばれた。holdoutを見て1000更新へ選び直すことはしない。

次に進むなら、更新数を増やす前に、新ゲームの対局中に学生と教師が異なる選択をした局面をゲーム単位で集め、実際に選んだ候補と教師候補を同深度で対照評価する。モデル容量/合法な盤面対称変換などの正則化を、複数のゲーム分割でゼロ補正より安定して良いか先に検証する。少数validationの最大値のみで進めず、教師値の汎化と実戦の両gateを再設計する。今回のholdoutやcheckpointを再選択に使わない。追加データや長時間更新を機械的に消費する根拠は得られていない。
