# Additional dev-selected stopping study

Added after observing the held-out learning curves, while the original final-epoch validation was still running. At this decision point only progress counts, not match outcomes/aggregates, had been inspected. This is an explicit extension, not a replacement or rescue of the original fixed16epoch study. Its full comparisons and its preregistered confirmation branch remain unchanged and will be reported separately.

Reason: all three architectures show rising held-out error after an earlier minimum. More training data helps, but taking the final16epoch checkpoint penalizes overfitting. A fair practical comparison should also use a predeclared development-based stopping rule, without choosing on test matches.

Use the same3072training games/84361states and192development games/5253states. For each architecture, select one epoch by minimum mean development MSE across all3seeds (including epoch0, earliest tie); apply that same epoch to all3seeds. This gives A6, B5, C7, recorded in earlystop-epochs.json. Do not select seeds, change architecture/loss/LR/batch, or add data. Reconstruct from frozen original weights with the same optimizer, permutation order and deterministic arithmetic; verify train/dev error against the corresponding recorded epoch, plus policy immutability. Thus update counts differ by architecture under the common stopping rule. This is not an equal-update architecture-only causal comparison.

After all original timed comparisons finish, train the9 stopped models. Freeze their hashes and a NEW32-prefix bank (random seed696000000;8/10/12ply) before any stopped-model matches. Exclude original training index, historical exclusions, current train/dev, current curve/validation/confirmation starts and their completed visited states. No reuse of any original test bank for selection or confirmation.

Evaluate A/F,B/F,C/F,A/C,B/C,192games each (32prefixes x both seats x3seeds),960total; width4,max6,500ms,torch1thread,nativeCPU,core0, no concurrent heavy work. F is frozen original gen3+H. Four primary comparisons are A/F,A/C,B/F,B/C; C/F is descriptive. Prefix-cluster bootstrap20k draws with fixed seed771,98.75%two-sided intervals (Bonferroni four comparisons), report WDL/point/score/time/depth/seeds. No additional validation screen is used: development data chose the checkpoints, and this one new bank is the independent test.

A or B supports an adoption recommendation only if both its F and C primary comparisons have point lowerCI>50% (numerical tolerance1e-9), positive mean score difference, and at most1%nonpass moves>550ms. If both pass, higher exact F point count wins, tieA. Do not promote C or perform further tuning/extra sampling. Human/empty-board superiority is not tested. Keep main/Frozen unchanged; publish results and saved models in the existing draft PR, with independent legal/score/split/hash audit.
